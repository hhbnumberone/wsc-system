工点与设备（现场录入）

填好上面的两项，先点「请平台核对」。
工点 ID 必须先在平台上建档，终端只能引用、不能自己编 —— 和桩号是同一个道理。平台没有的工点 ID 会被当场拒掉，并告诉你平台上有哪些。
设备编号可以改，但同样要过平台核对，改完会留一条 identity_change 记录（原编号、新编号、原工点、新工点）。 换编号前必须先结清欠账：本地还有没传完的数据时，两个按钮都会拒绝 —— 那些数据的 ID 里嵌着旧编号，换了编号再传，平台会按设备不匹配整批拒收。
桩号仍然没有输入框：这里是身份，不是桩号。

故障注入（演示用）

注入的是确定性的偏差：几秒内爬到目标值、保持一段时间、再自己退回去。 平台侧的报警按边沿触发 + 回滞判定，所以这里注入一次， 平台那边应该只出现一条报警 —— 不是刷一屏。
